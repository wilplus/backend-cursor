## 1. THE GATE — nothing here is optional before the first non-founder records

### 1.1 · P1 — stop serving recordings over permanent public URLs
**Owner: agent. In flight.**

The object storage bucket holding session audio, uploaded Takes, extracted
speech clips and slide decks is publicly readable, and the application prefers
that public address over the signed, short-lived URL it already implements.
Object keys embed UUIDs so nothing is enumerable, but any URL that leaves our
systems grants unrevocable access forever. This is DPIA RISK-11.

1. Find every code path that returns or embeds a storage URL for user content.
   **Enumerate them in the PR description** — the list is the deliverable as
   much as the fix.
2. The signed, short-lived URL becomes the only flavour any of them returns. The
   public address must not appear in any response payload, template, export,
   email or log line.
3. Every consumer requests a fresh URL on expiry instead of caching one: the
   player, downloads, the coach surface.
4. A test that fails if any handler returns a public-bucket-pattern URL.
5. State what this does NOT close: URLs already outside our systems stay valid
   until the bucket itself stops being publicly readable. Propose that ACL change
   as a separate follow-up with its own rollback. Do not execute it here.

**Done when:** no code path can emit a public URL, a test proves it, and
record → process → Ideal Text → next Take still works end to end.

### 1.3 · Prove `enforce` mode is really on
**Owner: agent or founder. Ten minutes.**

Doc 01 §7 makes `PLF1_PROCESSING_AUTHORIZATION_MODE=enforce` a condition of the
approval, on every service. This got **more** important, not less, once we
established that `Phase1AcceptanceGate` fails open: the client deliberately does
not block, because the backend is the enforcement authority. If enforce is off
anywhere, a user with no valid receipt sails past both.

It is logged twice per service, at container start:

- shell, before Python boots — `bin/railway-web.sh:15`, `bin/railway-worker.sh:39`
  ```
  [startup] PLF1_PROCESSING_AUTHORIZATION_MODE=enforce
  ```
- Python, at boot — `app.py:344`, `worker.py:263`
  ```
  gate flags PLF1_PROCESSING_AUTHORIZATION_MODE=enforce TAKE_FEEDBACK_POLICY_V3_MODE=...
  ```

Read the **boot log**, not the Railway panel. The panel shows what somebody
typed; the log shows what the process read. An unset variable prints `(unset)`
because the echo is deliberately unconditional.

**A real gap, and it belongs with this task.** None of the seven
`bin/railway-*-cron.sh` scripts echo the flag at all, and
`tests/test_railway_boot_scripts.py` pins `BOOT_SCRIPTS` to web and worker only.
`services/gate_flags.py`'s own header says the B-1 audit fixed this because "the
worker and the crons had no observable surface at all" — the fix reached two of
three. **The cron is what runs the purge**, so the service responsible for our
retention promises is the one whose configuration cannot be observed. Add the
echo to every cron script and extend `BOOT_SCRIPTS` so the next script added
cannot skip it.

### 1.4 · Prove the retention rules actually run
**Owner: agent. One query, then a decision.**

The published privacy copy makes deletion promises with periods in them. Two
switches decide whether any of it happens: a rule must exist in
`data_retention_rules` for each category, or `services/data_purge.py:231` no-ops
with `RETENTION_RULE_UNRESOLVED`; and `PHASE1_PURGE_EXECUTION_ENABLED` must be
on, or `scripts/run_phase1_data_purge.py:48` gates the whole run.

The query that settles it:

```sql
SELECT count(*) FROM data_purge_events;
```

**If that is zero, nothing has ever been deleted.** Then check the env var on
the cron service's boot log (see 1.3 — it may not be observable yet) and check
that `data_retention_rules` covers every category the privacy copy makes a
promise about.

This is the same shape of problem as the "opt-in and off by default" claim that
already had to be corrected: a published statement the system does not perform.

**Done when:** every retention promise in the published copy maps to a rule that
demonstrably runs, or the copy is corrected to match reality. Report, do not
quietly change the copy — it is hashed and needs a new policy version.

## 4. TRAPS THAT HAVE ALREADY BITTEN. Read before you write code.

1. **`register_phase1_policy_v1` raises `PURPOSE_CONTROL_VERSION_CONFLICT`** if
   any of `capability_version`, `reviewed_at`, `retention_control_version`,
   `deletion_control_version` or `rights_control_version` differs by one
   character from the registry for an operational purpose. `reviewed_at` was
   written with `now()`, so it cannot be retyped — **read all five back**.
2. **Purposes built with `jsonb_agg` fail silently.** A missing id publishes a
   smaller policy with no error. Always count the rows first.
3. **Merging a migration RUNS it in production.** `MIGRATE_ON_BOOT=1` and
   `bin/railway-web.sh` apply pending migrations during container start.
4. **Policy publish scripts are NOT migrations** and stay out of
   `migrations/manifest.txt`. Publishing a consent policy is not something a
   deploy should do behind anyone's back.
5. **CONFIG-FIRST.** Any environment variable goes on web, worker AND cron
   *before* the PR merges, verified from each boot log. A writer service missing
   the variable is the worst case: the web app looks healthy while background
   jobs silently drop their writes.
6. **`scripts/local_ci.sh` is the gate.** An ad-hoc `pytest && ruff && mypy` is
   not the job — a dev box's system `mypy` was a major version behind the pin and
   passed five real type errors.
7. **Hashed copy is byte-exact.** Never reformat, re-wrap or retype the four
   policy documents. Edit them in place or not at all.
8. **Never write "fully compliant."** `docs/PHASE1-PROCESSING-RUNBOOK.md` forbids
   the phrase. Report the controls actually verified and name what is not.
