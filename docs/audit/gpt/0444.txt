CONTEXT. The app is willab (WillpowerLab): a speaker records a Take of a slide
presentation; the backend transcribes it per slide, keeps one persistent Ideal
Text document, and a Manager surfaces evidence-backed Feedback; blind coaches
and peers rate moments of the recording. Fences that every change must keep:
AC-9 (no number, score, ratio, count or classifier output ever reaches a user
payload; every read a user sees is qualitative), BLIND COACH (nothing about a
moment, not the speaker's answer, not the machine's read, reaches a coach
before that coach's own blind answer on it), LIVE LOOP (record -> process ->
Ideal Text -> next Take never waits on a coach or on a side write; a failing
side write never blocks serving), CONSTRUCT (every measured state has one
written operational definition and asks exactly one thing), and the
provenance walls L3 (owner, peer, coach, machine and detector answers are
stored and read apart, never mixed; speaker taps are never blind labels).
Deployment: Railway with MIGRATE_ON_BOOT=1, so merging a migration to main
applies it to the production database during the next container start,
before the app process boots; migrations are append-only, idempotent and
forward-only (rollback is a new migration). The database is Supabase
Postgres 15: the browser roles anon and authenticated are granted on the
public schema by default and PostgREST publishes every function in public at
/rest/v1/rpc, so each file revokes those defaults itself and grants
service_role exactly what the Flask app needs; the app reaches the database
only with the service key (service_role), never as a browser role. The
rehearsal tier applies every migration twice to a disposable cluster and runs
a Postgres test against it before a push.

THIS MIGRATION (0444). The founder's QG12a A says that when the speaker's one answer disagrees with the machine's read of a moment, the coach gets that moment back as 'they disagree'; P26b A puts that ask in the coach's usual work list; P26c signs three lines for it that on purpose say neither why nor what the speaker answered, so the coach's second answer stays blind. Today the disagreement is already computed by the follow-up matrix in the app (services/judgement_follow_up.py: the request's kind or answer_kind becomes 'ambiguity'), but a coach who already judged the moment never hears of it. This file adds one table, coach_listen_again_requests (the Take, the moment, the coach, the KEY of one of the three signed lines, when asked, when heard; by its shape no reason, no answer, no read), and two SECURITY DEFINER functions: request_coach_listen_again_v1(take, snippet) writes one open row per coach with a blind judgment of record on the clip (confidence_labels lane 'coach', not a self-report, not an Audio-unclear abstention), none for a coach who has not judged it (it is still in their queue to judge blind), none twice while one is open, with the line key rotating A, B, C per coach, and returns how many rows it wrote (a log count, never a user payload); mark_coach_listen_again_heard_v1(snippet, coach) stamps heard_at on that coach's open row. The app calls the first as a side write wherever the matrix writes the ambiguity (three places; never raises, LIVE LOOP), and the second after a coach's reconsideration is kept (the rating route; contract 34, 0427). While a coach has an open row on a moment, _coach_state_map (the one map every blind door reads: the moment gate behind the moment read, drafts, named errors and practice judgement; the session read's transcript and owner-answer release) masks that coach's earlier answer, so those doors answer 409 again until the new blind answer lands; the queue lists the moment as state 'listen_again' with the line key and nothing else, not even the kind. confidence_labels is read, never altered, no trigger. service_role: SELECT and DELETE on the table (the queue read and the purge), EXECUTE on both functions, no INSERT or UPDATE by hand. Purged with the Take and with the coach.

CREATE OR REPLACE FUNCTION public.request_coach_listen_again_v1(
    p_take_session_id text,
    p_snippet_id text
) RETURNS integer
LANGUAGE plpgsql SECURITY DEFINER SET search_path = public
AS $$
DECLARE
    v_snippet uuid;
    v_coach   text;
    v_written integer := 0;
    v_prior   integer;
BEGIN
    IF COALESCE(btrim(p_take_session_id), '') = ''
       OR COALESCE(btrim(p_snippet_id), '') = '' THEN
        RAISE EXCEPTION 'COACH_LISTEN_AGAIN_INPUT_INVALID';
    END IF;
    BEGIN
        v_snippet := p_snippet_id::uuid;
    EXCEPTION WHEN invalid_text_representation THEN
        RAISE EXCEPTION 'COACH_LISTEN_AGAIN_INPUT_INVALID';
    END;

    -- Every coach with a blind judgment of record on this clip: the
    -- ledger's coach lane, no self-report, no abstention (the same rows the
    -- quorum counts as a coach's vote). A coach who has not judged it yet
    -- still has it in their queue to judge blind: nothing to add.
    FOR v_coach IN
        SELECT DISTINCT label.rater_id::text
          FROM public.confidence_labels label
         WHERE label.snippet_id = v_snippet
           AND COALESCE(label.state_id, 'confidence') = 'confidence'
           AND label.lane = 'coach'
           AND COALESCE(label.self_report, false) = false
           AND COALESCE(label.unrateable, false) = false
           AND label.value IN ('yes', 'in_between', 'no', 'not_sure')
           AND label.rater_id IS NOT NULL
         ORDER BY 1
    LOOP
        IF EXISTS (SELECT 1 FROM public.coach_listen_again_requests
                    WHERE snippet_id = p_snippet_id AND coach_id = v_coach
                      AND heard_at IS NULL) THEN
            CONTINUE;
        END IF;
        -- The three signed lines rotate per coach: A, B, C, A ... never the
        -- same twice in a row (N52.6, N54.1).
        SELECT count(*) INTO v_prior FROM public.coach_listen_again_requests
         WHERE coach_id = v_coach;
        INSERT INTO public.coach_listen_again_requests (
            take_session_id, snippet_id, coach_id, line_key
        ) VALUES (
            p_take_session_id, p_snippet_id, v_coach,
            (ARRAY['P26c-A', 'P26c-B', 'P26c-C'])[(v_prior % 3) + 1]
        );
        v_written := v_written + 1;
    END LOOP;
    RETURN v_written;
END;
$$;

CREATE OR REPLACE FUNCTION public.mark_coach_listen_again_heard_v1(
    p_snippet_id text,
    p_coach_id text
) RETURNS integer
LANGUAGE plpgsql SECURITY DEFINER SET search_path = public
AS $$
DECLARE
    v_closed integer;
BEGIN
    IF COALESCE(btrim(p_snippet_id), '') = '' OR COALESCE(btrim(p_coach_id), '') = '' THEN
        RAISE EXCEPTION 'COACH_LISTEN_AGAIN_INPUT_INVALID';
    END IF;
    UPDATE public.coach_listen_again_requests
       SET heard_at = now()
     WHERE snippet_id = p_snippet_id AND coach_id = p_coach_id AND heard_at IS NULL;
    GET DIAGNOSTICS v_closed = ROW_COUNT;
    RETURN v_closed;
END;
$$;

def flag_disagreement(database: Any, *, take_session_id: Any,
                      snippet_id: Any) -> int:
    """The disagreement flag fired on this moment (QG12a A): ask every coach
    with a judgment of record to listen again. Returns the number of asks
    written, for the log; 0 when none was needed or the write failed. Never
    raises: the speaker's answer is already saved."""
    if not take_session_id or not snippet_id:
        return 0
    writer = getattr(database, "request_coach_listen_again", None)
    if writer is None:
        return 0
    try:
        written = writer(str(take_session_id), str(snippet_id))
    except Exception as e:  # noqa: BLE001 -- a side write, named, never raised
        _log.warning("listen-again ask not written take=%s snip=%s: %s",
                     take_session_id, snippet_id, e, exc_info=True)
        return 0
    try:
        count = int(written or 0)
    except (TypeError, ValueError):
        count = 0
    if count:
        _log.info("listen-again asked take=%s snip=%s coaches=%d",
                  take_session_id, snippet_id, count)
    return count

def masked_state(state: Optional[dict], line_key: str) -> dict:
    """The coach_state of a moment with an open ask: the coach's own earlier
