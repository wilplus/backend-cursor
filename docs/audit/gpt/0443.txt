CONTEXT. The app is willab (WillpowerLab): a speaker records a Take of a slide
presentation; the backend transcribes it per slide, keeps one persistent Ideal
Text document, and a Manager surfaces evidence-backed Feedback; blind coaches
and peers rate moments of the recording. Fences that every change must keep:
AC-9 (no number, score, ratio, count or classifier output ever reaches a user
payload; every read a user sees is qualitative), BLIND COACH (nothing about a
moment, not the speaker's answer, not the machine's read, reaches a coach
before that coach's own blind answer on it), LIVE LOOP (record -> process ->
Ideal Text -> next Take never waits on a coach or on a side write; a failing
side write never blocks serving), CONSTRUCT (every measured state has one
written operational definition and asks exactly one thing), and the
provenance walls L3 (owner, peer, coach, machine and detector answers are
stored and read apart, never mixed; speaker taps are never blind labels).
Deployment: Railway with MIGRATE_ON_BOOT=1, so merging a migration to main
applies it to the production database during the next container start,
before the app process boots; migrations are append-only, idempotent and
forward-only (rollback is a new migration). The database is Supabase
Postgres 15: the browser roles anon and authenticated are granted on the
public schema by default and PostgREST publishes every function in public at
/rest/v1/rpc, so each file revokes those defaults itself and grants
service_role exactly what the Flask app needs; the app reaches the database
only with the service key (service_role), never as a browser role. The
rehearsal tier applies every migration twice to a disposable cluster and runs
a Postgres test against it before a push.

THIS MIGRATION (0443). Communities (migration 0432) let a speaker share one Take with the general community or private ones, per Take and revocable; the share row take_shares already stamps consent_version, the Privacy/Terms version the speaker's authorization was on. The founder's CM2 B (N53.2) switches sharing on with the sharing screen, under the founder's own signed words for it and without waiting for counsel, with the consent stamped with the version of the words the speaker saw; Q-B6 A (N62) adds that sharing names the current Privacy/Terms and that 'None' takes the share back. This file adds one nullable text column, take_shares.share_words_version. The app (share_take) now refuses a share whose body has no well-formed share_words_version (400 SHARE_WORDS_VERSION_REQUIRED, before the policy check), requires the speaker's current authorization to be on the named Privacy/Terms version (409 TERMS_REACCEPT_REQUIRED otherwise; the config constant now names phase1-2026-10-02, Privacy 3.3 + Terms 3.3, the same version the peer share and the blind check use), and stamps both versions on each share row; 'None' still revokes every live row with no version. The queue reads the live view community_clips_live, which does not carry either version, so a revoked share leaves every queue as before. COMMUNITIES_ENABLED stays False in this PR: every community route still answers 404 and nothing is written in production; take_shares has never taken a production row, so the ALTER locks an empty dark table. Grants are 0432's, restated: browser roles and PUBLIC hold nothing on take_shares; service_role reads and writes it (the app writes shares with the service key; there is no function).

-- Idempotent: ADD COLUMN IF NOT EXISTS; applied twice it changes nothing.

-- Rollback (a new forward migration): ALTER TABLE public.take_shares DROP
-- COLUMN share_words_version. Nothing else reads it.

BEGIN;

ALTER TABLE public.take_shares
    ADD COLUMN IF NOT EXISTS share_words_version text NULL;

COMMENT ON COLUMN public.take_shares.share_words_version IS
    'The version of the sharing screen''s words the speaker saw when they '
    'shared (0443; CM2 B, N53.2; Q-B6 A, N62), as the screen sent it. '
    'Beside consent_version (the Privacy/Terms version). NULL only on a row '
    'written before 0443; a revocation stamps revoked_at and reads no words.';

-- ── The door, restated (0432) ────────────────────────────────────────────
-- Browser roles and PUBLIC hold nothing on take_shares; the app reads and
-- writes it with the service key. Roles are guarded: they exist on Supabase,
-- not on a bare Postgres.
REVOKE ALL ON TABLE public.take_shares FROM PUBLIC;
DO $$
DECLARE
    v_role text;
BEGIN
    FOREACH v_role IN ARRAY ARRAY['anon', 'authenticated'] LOOP
        IF EXISTS (SELECT 1 FROM pg_roles WHERE rolname = v_role) THEN
            EXECUTE format('REVOKE ALL ON TABLE public.take_shares FROM %I', v_role);
        END IF;
    END LOOP;
    IF EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'service_role') THEN
        GRANT SELECT, INSERT, UPDATE, DELETE ON TABLE public.take_shares TO service_role;
    END IF;
END $$;

COMMIT;
----- END -----

    def upsert_take_share(self, *, take_session_id: str, owner_user_id: str,
                          community_id: str, consent_version: str,
                          share_words_version: str) -> Optional[dict]:
        """Share one Take with one community: one row per pair; a share
        clears revoked_at and stamps the consent version (Privacy/Terms) and
        the version of the sharing screen's words the speaker saw (0443,
        CM2 B). Raises on failure."""
        res = (self.client.table("take_shares").upsert({
            "take_session_id": str(take_session_id), "owner_user_id": str(owner_user_id),
            "community_id": str(community_id), "consent_version": str(consent_version),
            "share_words_version": str(share_words_version),
            "shared_at": datetime.now(timezone.utc).isoformat(), "revoked_at": None,
        }, on_conflict="take_session_id,community_id").execute())
        return (res.data or [None])[0]

    def revoke_take_shares(self, take_session_id: str, *,
                           keep_community_ids: list[str]) -> int:
        """Withdraw the Take from every community not kept; the rows stay
        with revoked_at stamped. Raises on failure."""
        query = (self.client.table("take_shares")
                 .update({"revoked_at": datetime.now(timezone.utc).isoformat()})
                 .eq("take_session_id", str(take_session_id))
                 .is_("revoked_at", "null"))
        keep = [str(c) for c in keep_community_ids or [] if c]
        if keep:
            query = query.not_.in_("community_id", keep)
        return len(query.execute().data or [])
