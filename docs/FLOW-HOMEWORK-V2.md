# Homework Flow v2 — Design

This document describes the **homework flow** from first warm-up to final report, and how it maps to the **admin panel** and **backend**. This flow **replaces** the current v2 dashboard flow (universal_questions → one recording → post_questions). Performance score **formulas** (performance_score_1, performance_score_2, performance_score_end) are left for a later phase.

**Locked decisions and implementation plan:** see **`V2_FLOW_UNDERSTANDING_AND_IMPLEMENTATION_PLAN.md`**.

---

## Flow overview

| Step | User sees / does | Admin panel | Backend |
|------|------------------|-------------|---------|
| 1 | **task_warm_up** text → records **recording_1** | task_warm_up: list per student (CRUD) | 3 metrics (strength, fillers, pacing) → **performance_score_1** (0–1) |
| 2 | AI-generated task: **context_short** + **focus_task** + **metric_question_1** + **metric_question_2** | context from AI; focus_task list per student (CRUD); metric_question_1/2 in Metrics section (CRUD) | performance_score_1 selects focus_task (min score filter; if >1, random.shuffle); context_short from recording_1 (AI) |
| 3 | User answers metric_question_1 & 2 → AI generates **final_task** (context + focus_task + metric_answer_1 + metric_answer_2) → user records **recording_2** | — | **performance_score_2** from 5 metrics (0–1) |
| 4 | **Questions** (or skip if none) | Admin chooses questions; CRUD questions; if none, step skipped | Answers saved to **questions** |
| 5 | **Report**: context_short, performance_score_end, answers; AI delivers | Admin can edit/overwrite report; stored in **context_long** | performance_score_end = (performance_score_1 + performance_score_2) / 2; report from AI |
| 6 | User finishes; report to admin; history; context_long updated | History tab; admin can update params and **send homework** to student | Report stored; context_long updated |

## Data model (new / updated)

### 1. Warm-up tasks (per student)

- **Table:** `v2_warm_up_tasks`
- **Columns:** `id`, `user_id` (FK auth.users), `text` (task_warm_up content), `order_index`
- **Admin:** CRUD list per student (student profile → Warm-up tasks section). **Admin assigns which one** the student sees: one task from the list is “assigned” (e.g. `assigned_warm_up_task_id` in `v2_student_overrides`). Student only ever sees that one warm-up task per run.

### 2. Focus tasks (per student, with min score)

- **Reuse:** `v2_tasks` (id, title, prompt_text, **min_task_score**, max_task_score, is_active).  
  Treat as **focus_task**: `min_task_score` = minimum **performance_score_1** for this task to be offered.
- **Selection:** Filter tasks where `min_task_score <= performance_score_1` (e.g. if performance_score_1 is 0.1, only tasks with min_task_score ≤ 0.1 are eligible; tasks with min 0.2 are not). If several match, `random.shuffle()` and pick one.
- **Admin:** List per student (already: assigned_next_task_ids); admin can also manage global pool (Tasks tab) and assign which tasks are available per student.

### 3. Metric questions (2 questions for AI task block)

- **Table:** `v2_metric_questions`
- **Columns:** `id`, `position` (1 or 2), `text`
- **Admin:** Metrics section: edit / delete / add metric_question_1 and metric_question_2.

### 4. Session / run context and scores

- **v2_sessions** (or one run per “homework”): store **context_short** (from recording_1), **context_long** (report / admin-overwritten), **performance_score_1**, **performance_score_2**, **performance_score_end**, **recording_1_id**, **recording_2_id**, focus_task_id, metric_answers, question_answers, report_id.
- **Recordings:** recording_1 and recording_2 linked to session; metrics and scores can live on recordings or be derived and stored on session (placeholders until formulas are defined).

### 5. Questions (post–recording_2)

- **Existing:** `v2_post_recording_questions_pool` + student overrides `assigned_post_question_ids`.  
  No change; admin chooses which questions; if none, step skipped.

### 6. Report and context_long

- Report generated by AI from context_short, performance_score_end, answers.
- **Append with timestamps:** Reports are appended (not replaced) so there is a full history. Store as a list of entries, e.g. `[{ "at": "ISO8601", "text": "..." }]` (backend: `context_long_entries` JSONB). Admin can view/edit/overwrite (e.g. append a new entry or update latest); can summarize later with AI if needed.

## Admin panel sections (summary)

| Section | Where | What |
|---------|--------|------|
| **Task warm-up** | Student profile | List of task_warm_up items; add, edit, delete, reorder; **assign which one** the student sees (single selection). |
| **Focus tasks** | Student profile + Tasks tab | Assign which tasks are available for that student; each task has min_task_score (used with performance_score_1). |
| **Metric questions** | Metrics (admin) | metric_question_1 and metric_question_2; add, edit, delete. |
| **Questions** | Student profile + Questions tab | Which post-recording questions the student sees (existing). |
| **Report / context_long** | Student history (session detail) | View report; edit / overwrite; stored as context_long. |
| **Send homework** | Student profile | Existing “Send homework” action. |

---

## Backend (placeholders for scores)

- **performance_score_1:** computed from 3 metrics (strength, fillers, pacing) on recording_1 — **placeholder** (e.g. return 0.5) until formulas are defined.
- **performance_score_2:** computed from 5 metrics on recording_2 — **placeholder**.
- **performance_score_end:** `(performance_score_1 + performance_score_2) / 2` — **placeholder** when both are placeholders.

All flow steps (warm-up → focus_task selection → final_task → recording_2 → questions → report) will be implemented so that when real score formulas are added, they drop in without changing the flow.

---

## Implementation order

1. **Migrations:** v2_warm_up_tasks, v2_metric_questions; v2_sessions (or equivalent) columns: context_short, context_long, performance_score_1, performance_score_2, performance_score_end, recording_1_id, recording_2_id.
2. **Admin CRUD:** warm-up tasks (per student), metric questions (list of 2).
3. **Student flow endpoints:** get warm-up task, submit recording_1, get AI task (context_short + focus_task + metric_question_1/2), submit metric answers, get final_task, submit recording_2, submit question answers, get/save report, update context_long.
4. **Admin:** report overwrite (context_long) in history/session detail.
5. **Later:** Replace score placeholders with real performance_score_1, performance_score_2, performance_score_end calculations.
