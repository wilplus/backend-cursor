<script src="https://willpowerlab.com/w.js" data-key="ws_7f3k…" async></script>
Plain HTMLBefore </body> in the template. ShopifyOnline Store → Themes → Edit code → theme.liquid, before </body>. WordPressAny "header and footer scripts" plugin, footer slot; or the theme's footer.php. Tag ManagerA Custom HTML tag on all pages. Same line. Only some pagesPaste it on the product and head-spa pages only. The key is the same.

What the tag does on their page

  1. Reads its key and fetches the workspace: Mila's name, colour, the answerer, the signed words. The key works only from the domains listed on the workspace.
  2. Mounts one element at the end of the page, inside a shadow root, so Mila's CSS and ours never touch. On this demo page, open the browser's inspector and look for #wpl-widget.
  3. On tap, opens the form as an iframe to willpowerlab.com/w/<key>/ask, so the photo, the number and the consent never pass through Mila's page or Mila's other scripts. This demo draws it inline, because the demo page cannot embed a second site.
  4. Send posts to /v2/public/requests: the key, the words, the photo, the number, the consent tick and its wording version. The answer is a request id, nothing else. A guest identity for Ola and one request row in Mila's workspace come out of it, and the request lands in Marta's chat.
  5. Nothing stays on Mila's site. The page can listen for wpl:sent to count conversions in its own analytics; it never sees the content.
